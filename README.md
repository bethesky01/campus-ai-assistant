# Campus AI Assistant — LAB1

A local browser-based RAG assistant and admin knowledge base for a college workshop. Administrators
upload policy PDFs; students ask questions answered from retrieved passages with document/page sources.
All bundled policies refer to the fictional **Demo Institute of Technology**.

LAB1 provides RAG and the Admin Knowledge Base. LAB2 adds structured routing, local learning-resource
tools, General AI, streaming, clarification, and in-memory history. LAB3 adds input and document
guardrails, injection detection, evidence checks, output validation, scope handling, safety metadata,
and a workshop functional evaluation.

## Architecture

```text
Admin:   PDF → validation → page extraction → chunks → EmbeddingGemma → ChromaDB
Student: question → EmbeddingGemma → similar chunks → grounded prompt → Qwen3 → answer + sources
```

LAB2 student routing:

```text
Question → Router → College Policy RAG / Learning Resource Tool / General AI → SSE stream → UI
```

PDFs and the JSON registry live in `data/documents/`; vectors persist in `chroma_db/`. No document is
sent to a cloud service and documents are not automatically ingested at startup.

## Prerequisites

- Python 3.11 or newer
- [Ollama](https://ollama.com/) running locally
- Qwen3 8B and EmbeddingGemma model tags installed in Ollama

Check the exact tags on your machine before configuring the app:

```powershell
ollama list
```

If needed, obtain the configured models (tag availability can vary):

```powershell
ollama pull qwen3:8b
ollama pull embeddinggemma
```

## Setup

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `.env` so the model tags exactly match `ollama list`:

```dotenv
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_LLM_MODEL=qwen3:8b
OLLAMA_EMBEDDING_MODEL=embeddinggemma
CHUNK_SIZE=800
CHUNK_OVERLAP=120
TOP_K=4
RETRIEVAL_SCORE_MARGIN=0.25
MAX_UPLOAD_SIZE_MB=10
CHROMA_COLLECTION=campus_knowledge_base
```

Start Ollama, then run the app:

```powershell
python run.py
```

- Student assistant: <http://127.0.0.1:8000/>
- Admin knowledge base: <http://127.0.0.1:8000/admin>
- Readiness details: <http://127.0.0.1:8000/health>
- Interactive API docs: <http://127.0.0.1:8000/docs>

## Add knowledge

At `/admin`, enter a title, select Attendance, Examination, Placement, Internship, or Other, choose a
text-based PDF, and select **Upload & Process**. The result reports pages and chunks. The document list
supports targeted re-index and delete operations.

To create fictional workshop PDFs and ingest every PDF in `data/documents`:

```powershell
python scripts/create_demo_pdfs.py
python scripts/ingest_documents.py
```

Run bulk CLI ingestion while FastAPI is stopped; embedded Chroma clients should not be shared across
separate writer processes. The UI upload and CLI use the same processing service. Scanned image-only
PDFs need OCR before upload.

Example questions:

- What is the minimum attendance requirement?
- What are the examination eligibility rules?
- What are the placement eligibility criteria?
- What documents are required for placement registration?
- Give me a Generative AI roadmap. → Learning Resource Tool
- How should I learn Python? → Learning Resource Tool
- What are embeddings? → General AI
- What is the requirement? → Clarification

The browser keeps a session ID and the server retains a bounded recent history in memory. Restarting
the application clears conversation history; this is intentional for the workshop prototype.

## How RAG and grounding help

The question is embedded and ChromaDB returns the most semantically similar chunks. Those chunks are
placed in a system-controlled prompt that tells Qwen3 to answer only from them, treat uploaded content
as untrusted reference data, and acknowledge missing support. Sources are built from retrieved metadata,
not generated by the model. This reduces hallucination risk but cannot eliminate it; verify important
answers against the cited page.

## Troubleshooting

- **Health says Ollama is false:** start Ollama and check `OLLAMA_BASE_URL`.
- **Model is false:** compare `.env` against `ollama list`; tags must match exactly.
- **Upload saved but indexing failed:** confirm EmbeddingGemma is installed and Ollama is reachable,
  then use Re-index.
- **PDF has no extractable text:** run OCR on scanned PDFs first.
- **Weak retrieval:** adjust `CHUNK_SIZE`, `CHUNK_OVERLAP`, or `TOP_K`, then re-index.
- **Unrelated source cards:** lower `RETRIEVAL_SCORE_MARGIN`. It keeps Chroma results whose distance
  is close to the best match; overly small values may remove useful supporting passages.
- **Reset workshop data:** delete documents through the admin UI so PDFs, vectors, and registry entries
  stay consistent.

## Runtime logs and timing

The application logs workflow boundaries as `process_started`, `process_completed`, and
`process_failed`. Completed and failed operations include `elapsed_seconds`. Local model timings use
dedicated events:

```text
embedding_call_started model=embeddinggemma call_type=query item_count=1
embedding_call_completed model=embeddinggemma call_type=query item_count=1 elapsed_seconds=2.123
llm_call_started model=qwen3:8b
llm_call_completed model=qwen3:8b elapsed_seconds=15.581
```

Questions and extracted document text are intentionally excluded from logs.

## Responsible AI and limitations

LAB3 applies defense in depth: inputs, selected personal-data patterns, and prompt-injection patterns are checked before routing;
documents are scanned and always treated as untrusted data; policy evidence and sources are checked;
and final metadata is validated before buffered output is streamed. Live sports/weather requests are
handled as out of scope. These controls reduce risk but do not provide perfect safety, complete
injection detection, zero hallucinations, or guaranteed accuracy. Verify important answers against
official college sources.

The privacy guardrail recognizes selected email, Indian-style phone-number, and alphanumeric student-ID
patterns. It replaces detected values before routing, Ollama calls, and in-memory history, and scans the
output again. Use fictional data in demonstrations; this educational pattern detector is not a complete
privacy or data-loss-prevention system.
